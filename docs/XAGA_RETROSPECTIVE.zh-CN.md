# xaga 原生 Ubuntu 移植复盘

2026-10-29。目标设备为 Redmi Note 11T Pro（xaga / MediaTek MT6895）。项目按用户要求暂停，手机尚未安装 Ubuntu。

## 目标和授权边界

目标是真机原生 Ubuntu、保留 Android 双系统、ROS 2 运行环境以及完整硬件功能。容器、QEMU 和 chroot 仅用于开发期验证，不算手机交付。

用户后来取消个人及应用数据、完整 userdata 的备份，但这不授权擦除、格式化或重分区，也不取消启动链、GPT、校准等必要恢复证据。
离线开发不要求设备一直连接，不能通过重复轮询 ADB 代替开发。未核验恢复、启动和存储隔离之前，不刷写、重启、切槽或安装手机 Root。

## 实际完成的部分

### Ubuntu 和 ROS 2 候选

- Ubuntu 24.04 ARM64、GNOME、ROS 2 Jazzy、Mesa 25.2.8，以及原基线 6.18.0 模块已整合。
- 压缩 rootfs 为 972,603,537 bytes，SHA256 为 `1909fb4c6221f73a979a2dc50fb528dd23e6342fbcfa25540a82d96c530668b1`。
- 完整校验和严格 TAR 清点通过：104,608 成员、19,024 符号链接、3,539,749,613 bytes 普通文件数据。
- ARM64 QEMU/chroot 中 ROS CLI、Python import、ELF 架构和双向 C++/Python DDS 消息测试通过。
- 未解决交付登录、Linux 根存储、完整固件整合和 boot.img；未进行手机原生 ROS 验收。

### 诊断启动与固件

- 构建了仅提供受限状态查询的 no-libc AArch64 init，并将固定哈希的 cpio 内建进内核。
- 强制内建 initramfs 和命令行，禁用相关 marker、pstore 和 bootconfig 路径；真实 linker 范围及 Image 中的归档字节核对通过。
- 静态隔离不证明 bootloader、看门狗、USB、按键返回或整条启动链无持久副作用；这些仍未真机验证。
- 私有参考 ROM 的完整性、sparse super 转换、LP 主备元数据及 vendor EROFS 解码通过，受控提取了 21 个参考固件。
- Wi-Fi 实际选中 CONNAC2X2_SOC7_0 / AXI，而不是 MT7921E PCIe。参考设备树选择 `flavor_bin = "b_t"`，已独立准备精确匹配的主 Wi-Fi、MCU EMI 和 conninfra 配置组件。
- 主 Wi-Fi 文件名的末尾 `1` 是源码固定值，不是运行时 ECO；MCU EMI 文件名则使用 ECO。不得把两者混淆或随意换 b/c 变体。
- 实际面板、无线 ECO、本机 NV 校准、固件 ABI 和早期加载仍未验证。参考 ROM 数据不能替代本机校准。

### 验证范围

最近完整回归为 WSL 179 项通过，Windows 同一 discovery 有 22 项 Linux-only 跳过，其余通过。
测试覆盖归档、镜像、元数据、编译/打包保护、静态诊断和固件处理工具；不是 179 项手机功能验收。
早期失败记录保留，包括工具误拒 ET_DYN、QEMU 超时等，不能只展示最终绿色结果。

## 尚未解决的实质阻塞

1. 本机运行时 FDT、活动启动链、GPT 和必要校准/恢复材料不足。
2. 参考 ROM 与当前系统版本不同，回滚、恢复兼容性和联发科低级恢复入口未验证。
3. Android userdata 为加密 F2FS；无法把它直接当 ext4 根，也不能假定主线内核能解密。
4. 没有经过确认的双系统根存储和切换方案，不能把 B 槽假定为空。
5. 尚未真机最小启动，更没有显示、GPU、触控、无线、音频、蜂窝/VoLTE、相机、指纹、充电和休眠等完整验收。

## 最重要的教训

- **先证明路线可落地，再扩大构建。** 在根存储、恢复入口和本机证据缺失时，继续制造候选不等于更接近安装完成。
- **设置真机里程碑，但不越过安全授权。** 离线工具只能支持下一次明确的设备核对，不能无限替代它；证据窗口应集中，不要求设备整天连接。
- **不能用算力替代缺失信息。** 更多 tokens、更多编译和更多绿色 mock 测试不会自动补齐硬件文档、厂商协议或物理恢复能力。
- **原生桌面与全功能是不同验收层次。** 有 GNOME 截图不等于有 VoLTE、相机、指纹、低功耗和稳定恢复。未知必须明确标记。
- **不同平台不照搬。** 高通教程的分区号、DTB、boot 镜像和擦除命令不能套到联发科 xaga 上。
- **只读挂载也要考虑写入。** ext4 只读挂载可能涉及 journal replay；读取校准时应核对 `ro,noload`，但这仍不证明路径和文件系统选择正确。
- **版本号相同不代表模块兼容。** 两个内核都叫 6.18.0，不意味着可以混用其模块或配置。
- **参考 ROM 完整性不等于能救砖。** 哈希和头部检查不能证明匹配当前系统、回滚状态、AVB 或真实恢复路径。
- **如实记录执行状态。** 构建已退出就是已退出；持续目标的状态不代表应用关闭或电脑休眠后仍在工作，不能虚报后台推进。
- **交接应以产物和证据为中心。** 记录源码身份、实际结果、失败、下一步和授权边界；不让下一个 agent 重新下载、重新猜测或把部分完成当交付。

## 为什么改为已有平板方案

用户选择停止 xaga，转向已有发布和上游真机证据的 Pad 6 Pro 项目，以减少从零适配的不确定性。
这不意味着平板可以直接无风险刷入，也不意味着上游全部功能已完成；下一阶段是核对实际机型、容量、布局、恢复材料和数据清空授权，而不是宣称已安装。
